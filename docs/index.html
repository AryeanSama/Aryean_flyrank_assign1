Executive Summary

Can historical traffic volatility predict page-level search performance decay 30 days in advance? Using DuckDB over FlyRank search performance data, we constructed a 60-day temporal lookback matrix targeting page decay. A LightGBM classifier was evaluated using a time-aware out-of-time test split against a historical heuristic baseline. The final model achieved an ROC-AUC of 0.812 (+39.5% lift) and a Precision @ Top 10% of 0.684 against an 18.5% decay base rate.

Problem Framing

Decision Supported: Prioritizes underperforming pages for content updates and search intent re-alignment before traffic loss compounds.

Unit of Analysis: Page-level aggregates evaluated across 30-day rolling windows.

Output: 4-tier risk score (0.00 to 1.00 decay probability).

Human Action: Editorial teams review Tier 1 flagged pages to update outdated statistics, refresh metadata, or re-align search intent.

Cost of Error: False Positives waste editorial labor on stable pages; False Negatives cause unmitigated traffic loss over extended timeframes.

Data Safety & Governance

Data ingested via DuckDB from hf://datasets/flyrank/ml_internship_warehouse/*.parquet. Pages under 50 monthly impressions were excluded. Label-derived leakage fields (e.g., trend_direction, trend_pct) were deliberately dropped prior to training. All client identifiers were hashed into pseudonymous page IDs used strictly for grouping.

Baseline Comparison

Rule Baseline: Flags a page for decay (1) if recent 7-day average traffic drops below the prior 30-day average (impression_slope_7_30 < 1.0). Evaluated on the exact same test split, yielding an ROC-AUC of 0.582 and Precision @ Top 10% of 0.423.

Model Architecture

Method: LightGBM Classifier (100 estimators, max depth 3). Fits non-linear feature interactions without overfitting noisy time-series data.

Features Included: impression_slope_7_30, ctr_volatility_14d, 長position_drift_delta.

Target Definition: Binary flag ($Y=1$) if page traffic drops by ≥20% in the evaluation window ($T$ to $T+30$).

Evaluation & Performance

Split Design: Time-Aware Out-of-Time Split (Train: Months 1–4; Test: Months 5–6) to eliminate temporal data leakage.
